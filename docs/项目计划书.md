# Aegis 神盾 · ComputeShield

## IV 项目计划书：可验证的算力保障原型

协议机制版本 IV · 2026-10-08，当前交付 VI。VI 沿用 V 的视觉与 IV 的机制，增加独立访客的公开浏览器演示和移动端适配；公开版使用规则引擎，未连接真实模型、真实节点或资金交易。本文说明当前原型的机制、验证方法与后续工作。当前交付以本地运行与可复核文件为准，未将目标链连通性或钱包连接视作项目已部署。

## 1. 项目要解决的问题

算力服务具有可度量的履约指标，例如可用时长、请求延迟和算力输出。发生异常时，任务方、节点方与资金提供方需要共同理解保障范围、举证要求、争议处理和赔付边界。Aegis 将这些环节放入一个可运行的原型，检验规则、资金约束和用户流程是否一致。

当前交付适合机制研究、产品演示与技术评审。它没有通过生产安全审计，没有真实赔案外部标定，也没有形成可商用的去中心化预言机、争议治理或保险经营体系。

## 3. 合约机制与资金约束

合约由 NodeRegistry、RiskPool 与 ComputeShieldCore 组成。节点登记并质押；LP 按净资产取得份额；保单创建时预留承保额度。新保费作为待赚保费管理，在保障结束或案件结算时按规则转入可分配资产，减少短期资金进出截取保费的空间。

LP 提款按份额赎回，并受可用资本约束，不得抽走已锁定的赔付资金。赔付、驳回或无事故到期需要释放对应保单的资金预留。资金操作采用状态先更新再转账与重入互斥。具体行为以 IV 合约测试和本地交易报告为核查依据。

事故路径为：投保方提出请求，授权 reporter 提交观测时长与证据摘要后进入挑战期；未挑战案件按规则结算，被挑战案件由独立 arbiter 明确核准或驳回；逾期未裁决按合约超时路径关闭。挑战截止时间在触发时固定。

这是权限型证据与仲裁原型。reporter 和 arbiter 的地址职责分离，不能代替外部证据真实性保证、去中心化共识或法律争议机制。事故自报本身不能直接批准赔付。

## 4. 真实模型的职责与限制

项目验证页通过本地 Node 服务调用 Ollama，任务限于事故资料梳理。输出包含摘要、带原文引用的相关观测、缺失信息、建议处理路径及理由。建议为人工复核、补充证据或未识别明确事故，不直接转账、修改保单或批准赔付。

本机接入模型为 huihui_ai/qwen3.5-abliterated:9b，运行时精确标识以状态接口和报告为准。页面展示模型标识、执行时间和耗时。服务设有输入长度、请求超时、并发与输出结构校验；服务不可用时显示错误并保留原文，不用规则模板冒充模型回复。

真实模型的小样本评估与确定性 fixture 单元测试分别标记。小样本通过只说明已记录案例的结果，不是泛化准确率、对抗安全保证或业务批准。提示注入输入作为待分析资料处理，仍需持续扩展攻击评估。

## 5. 定价、LAE 与仿真边界

定价事实来源为 server/pricing.js。当前保费公式已包含理赔费用 LAE：

`保费 = (期望净损失 + 期望 LAE) ÷ (1 − 费用率 − 目标利润率) × 风险边际`

期望净损失考虑事故频率、严重度、保额、期间、再保分出与追偿；LAE 按险种通道结构加权。代码当前使用费用率 22%、目标利润率 15%、风险边际 1.10，直通件 LAE 45 BOT、编排件 LAE 380 BOT。参数是原型假设，不是保险合同或真实支付承诺。

severity-calibration、Monte Carlo 与随机组合报告使用内部生成事故样本和同一规则引擎。“标定”是仿真样本回灌，尚未经真实赔案外部标定。再保、追偿、费用和相关性假设变化会改变结果；不能从某组模拟无亏损推断零风险或稳定盈利。

## 7. 技术结构与运行

前端使用原生 HTML、CSS 与 JavaScript；Node 服务承载业务状态、静态资源和模型接口；Solidity 合约独立运行于 EVM。浏览器使用钱包签名执行链上操作，模型服务只负责生成辅助文本。

安装 Node.js 24 LTS后，在交付目录执行 npm install，再执行 npm start，打开 http://127.0.0.1:8788。需要模型研判时，先启动本机 Ollama 并确保状态接口返回可用。更换模型或服务地址使用项目环境配置。

工作台经营数据以本地服务会话为单位；协议演示数据不应被误认为资产余额。真实钱包操作前应核对当前模式、网络、代码校验与部署报告。当前版本不附带目标链部署私钥或资金。
